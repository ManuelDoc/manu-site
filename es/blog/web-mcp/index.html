¿Qué es WebMCP? Por qué podría ser importante para tu web muy pronto

Alguien abre ChatGPT y escribe: «búscame un chef privado para una fiesta de cumpleaños este sábado».

Lo que pasa a continuación es rápido y acertado, o lento, caro y equivocado. WebMCP es la razón por la que está a punto de convertirse en lo primero.

La explicación de diez segundos

Cuando un asistente de IA llega hoy a una web, en realidad no la «ve».

Ve un montón de botones sin etiquetar y tiene que adivinar. Prueba uno, hace una captura de pantalla, mira la imagen, vuelve a adivinar. Cada captura que tiene que interpretar le cuesta tiempo y tokens al asistente — piensa en los tokens como su factura de teléfono, y en una captura como una llamada cara.

WebMCP es un conjunto de instrucciones que una web puede entregar directamente a un agente de IA: así se reserva una mesa, así se consulta un precio, así se busca en el menú. Se acaban las conjeturas, se acaban las capturas de pantalla.

Por qué merece la pena saber esto antes de que esté en todas partes

Cada vez más gente le pide a un asistente que haga cosas por ella en lugar de buscar ella misma.

Encontrar un chef, reservar una mesa, pedir un presupuesto. Si tu web no puede responder con claridad, pasa una de dos cosas: el asistente se rinde y prueba con la competencia, o avanza a duras penas con el método lento y caro — y una respuesta lenta pierde un cliente tan rápido como una equivocada.

Esto no es solo un problema técnico. Es un problema de negocio, y aparecerá antes en las webs más difíciles de usar, mucho antes de que nadie te diga por qué han bajado las reservas.

Qué está pasando ahora mismo

Google y Microsoft están construyendo WebMCP juntos, dentro del Web Machine Learning Community Group del W3C. Chrome abrió un origin trial público en Chrome 149, anunciado en Google I/O en mayo de 2026, y Expedia, Booking.com, Shopify, Etsy, Instacart, Target, Credit Karma y TurboTax ya lo están probando.

Conviene ser precisos: está desactivado por defecto, Safari y Firefox no se han comprometido con él, y la especificación todavía está cambiando. Esto es muy pronto. Pero que dos de los mayores fabricantes de navegadores se pongan de acuerdo en el mismo enfoque desde el primer día no pasa a menudo.

Para developers: cómo funciona en realidad

WebMCP te da dos formas de exponer una acción, y cuál usar depende de qué tipo de acción sea.

Declarativa, para formularios normales. Si la acción ya es un formulario HTML normal, simplemente lo etiquetas. Unos pocos atributos nuevos le dicen al navegador qué hace el formulario, y él construye la descripción de la herramienta por ti — sin necesidad de JavaScript:

<form toolname="book-private-chef" tooldescription="Book a private chef for an event">
  <input type="date" name="date" toolparamdescription="Date of the event" required>
  <input type="number" name="guests" toolparamdescription="Number of guests" required>
  <button type="submit">Request a chef</button>
</form>

Imperativa, para todo lo demás. Si la acción no es un formulario — consultar una reserva, actualizar una cesta, cualquier cosa controlada por JavaScript — la registras directamente con la API modelContext del navegador:

await document.modelContext.registerTool({
  name: "check-booking-status",
  description: "Check the status of an existing booking by reference number",
  inputSchema: {
    type: "object",
    properties: {
      reference: { type: "string", description: "The booking reference number" }
    },
    required: ["reference"]
  },
  async execute({ reference }) {
    const status = await getBookingStatus(reference);
    return { content: [{ type: "text", text: `Booking ${reference} is ${status}.` }] };
  }
});

La mayoría de las webs de pequeños negocios solo necesitarán la primera. Si tus formularios ya están limpios y bien etiquetados, ya tienes hecha gran parte del trabajo antes de escribir una sola línea del nuevo código.

No deberías tener que estar pendiente de esto. Yo sí lo estoy.

Casi todo lo que cuenta este artículo se verá distinto dentro de un año. Nuevos atributos, más navegadores sumados, puede que hasta un nombre distinto para todo esto. Es normal en una fase tan temprana — y es exactamente por eso que no se le puede pedir a quien lleva un negocio que esté pendiente de esto además de todo lo demás que ya hace.

Esa parte me toca preocuparme a mí, no a ti.

Cuando construyo o mantengo una web, sigo de cerca lo que cambia por debajo — nuevos estándares, nuevas formas en que navegadores y asistentes de IA leen una página — junto con un pequeño equipo de agentes de IA que uso justo para esto. Tu web se actualiza en silencio, de fondo, para que sigas siendo fácil de encontrar con lo que sea que se use para buscar la próxima vez, sin que tengas que enterarte de que ha pasado.
